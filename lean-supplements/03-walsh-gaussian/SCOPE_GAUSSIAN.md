# Scope of the single-run Gaussian addition

Source: [pinned Paper 3 §4.2](https://github.com/dch-and-Elara/some-research-inspired-by-openais-eth-preprint/blob/95ad3fb52aeac8376ba835b76987ef5f9d6156d6/reconstruction-studies/papers/paper_ternary_codes.tex#L497-L511).
The source mathematical claim is deterministic time polynomial in the physical dimension D, slot count q, and rational label bit width L. This is in addition to the unchanged public build's independent direct coefficient compiler. The new path intentionally does not use that compiler or the previous scalar trace as its evaluator.

| New module | What its executable operation measures | Semantic and finite-budget evidence |
|---|---|---|
| P3BareissBitCells | Original checked binary scalar arithmetic and binary zero tests, then a charged signed-word decode where a stored integer is needed | paidZero_correct, paidInt_correct, scalar_output_size, paidInt_price |
| P3BareissBitForward | A zero test actually chooses the next scan transition; both forward products, their subtraction and exact division feed the next stored table | paidScan_correct gives the full tested prefix, paidForward_correct gives every actual table entry, paidForward_price counts all generated cells |
| P3BareissBitBackward | The selected pivot row and the actual returned common-denominator child solution drive each multiply/add of the dot product, subtraction and exact division, and the returned insertion | paidDot_correct, paidBackward_correct, paidBackward_price |
| P3BareissBitRun | At each reached state, candidate-roster/finite control debit, actual pivot scan, actual optional RHS scan, actual next table, recursive child result and only that child's conditional back substitution | paidRun_correct and paidRun_price; at most min(m,n)+1 reached frames |
| P3BareissBitPaper | Shared arrays of actual row-input and coefficient-writing runs; real row controller for every physical output word; writes the selected actual complete solution matrix | buildInputOnce_eq, writeMatrixOnce_eq, paidRow_correct, runGaussian_output, runGaussian_price, original_gaussian_counted |

The main declaration quantifies the same genuine input as the paper: q≥2, a q-entry input array of legally encoded fractions with width at most L, and its distinct nonzero rational node interpretations. It requires no guessed pivot roster, precomputed arithmetic trace, solved rows, external solver, or premise giving a cost cap. The existing original trace is consulted **only by the refinement proof** to certify when the binary primitives produce the same selected values, and to derive the legal width from the actual input. The tested order and forward result coincide with the original deterministic solver. All D × D × ((q−2)+1) output coefficient pairs are actually written. The final result and budget refer to the exact same runGaussian expression.

Fee units and scope: scalar arithmetic, exact division, zero testing, and reading/writing signed words are charged by the actual bit routines. The original generated entries and output coefficients include their existing public fees. The additional navigation/header debit uses the explicit padded dense bounded-word table access/control model. Visits, preparation and copies are charged at their actual selected stages; within a field, navigation is a conservative per-block debit, not an observed cycle count or a formal translation of Lean's evaluator to a generic single-tape Turing machine. The integer values and finite table indices are typed state in this model; the user input labels are already encoded data. The natural tally is annotation, not an extra time-normalized output.

The new clock uses a different explicit polynomial gaussianBudget(D,q,L), not an assertion that the old numeric constructionBudget constant still covers all additional navigation and decode charges. In the printed sense the polynomial claim is preserved. For S=D+q+L+3, the dimensions m,n and source width are O(S²), the derived scalar width B is O(S⁴), and navigation and scalar prices are O(S⁸). A reached frame is O(S¹²), there are O(S²) frames per physical row and D≤S rows. Creation of the original cells and writing the final coefficients have strictly smaller degrees. Hence the displayed envelope is conservatively O(S¹⁵); the Lean theorem uses the explicit polynomial, without assuming this asymptotic as a guard.
